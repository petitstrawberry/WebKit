# Host verifier tests

Run from the WebKit repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Source/WebCore/scarlet/DirectRenderer/tests -v
```

Every artifact and log generated by these tests is **synthetic test-only data**.
The tests invoke neither a build nor WebCore, Scarlet, a guest, or a renderer.
Passing tests establish that the host verifier enforces its artifact protocol
and causal comparison rules; they do not establish native rendering success.
Temporary files are removed automatically.

The verifier accepts schema 2 only and needs the externally expected run ID,
input and output prefix, plus the dedicated log for that one native execution.
For transferred artifacts, provide `--native-input` and `--native-prefix` so the
guest paths can be checked independently of the host destination. `--size`,
`--expect-element`, and `--expect-text ID=TEXT` add explicit caller expectations.
The dedicated log must include the guest harness's matching `CASE_BEGIN` and
`CASE_END` markers with `success=true code=0`; a renderer PASS alone cannot prove
that the native process returned successfully. `--case` can require the case name.
Run `python3 Source/WebCore/scarlet/DirectRenderer/verify.py --help` for the suite manifest contract.

The suite checks the seven bundled fixture inputs byte for byte, native DOM
text and bounds, decoded PNG/BGRA agreement, CSS width/color, DOM text, font
size, viewport reflow, and the unchanged script marker during resource attempts.
The script source itself legitimately occurs in body `textContent`. The measured
`script-marker` must remain unchanged, `script_execution_entries` and
`scripts_executed` must be zero, and `script_enabled` must be false. The mandatory
`SCARLET_SCRIPT_GUARD` log must match these metadata values. The upstream
`script_permission_attempts` counter records inquiries before permission checks;
it must be positive for `offline_attempts` and zero for the six ordinary cases.
It does not count actual VM execution.

Snapshot resources are available only through the imported API, with an explicit
frozen `SnapshotProfile` passed as the keyword-only `snapshot_profile` argument
to `verify`. The profile carries the exact document bytes, expected HTTPS
document URL and native index/root paths, and a mandatory trusted site validator.
The shared checks remain mandatory. Afterwards the site validator receives an
independent `VerifiedArtifact` copy including the same verified `native_log`;
it must check the frozen manifest/index, actual resource receipts and site layout,
return `None` on success and raise `VerificationError` on rejection. Unexpected
exceptions or other return values are rejected. No fallback is available.
The ordinary CLI and seven-case offline suite do not enable this profile.

FNV checksums and a supplied log correlate artifacts. They are not cryptographic
attestation of execution location; actual native-run and window-presentation
evidence must be collected separately.
